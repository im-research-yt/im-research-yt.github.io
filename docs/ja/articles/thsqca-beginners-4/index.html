練習用データ(第1回と同じ) 
make_demo_data <- function(n = 400, seed = 2026) {
  set.seed(seed)
  clip <- function(x) pmin(10, pmax(0, round(x)))
  QUA <- clip(rnorm(n, 6, 2))
  SER <- clip(rnorm(n, 6, 2))
  ENV <- clip(rnorm(n, 6, 2))
  core <- pmax(pmin(QUA, SER), pmin(QUA, ENV) - 1)
  LOY  <- clip(core + rnorm(n, 0, 0.7))
  data.frame(LOY, QUA, SER, ENV)
}

demo <- make_demo_data()

第1回のアウトカム閾値スイープを、再び使います。今回は、レポートに必要な、完全な詳細を求めます。

res_ots <- otSweep(
  dat            = demo,
  outcome        = "LOY",
  conditions     = c("QUA", "SER", "ENV"),
  sweep_range    = 5:8,
  thrX           = c(QUA = 7, SER = 7, ENV = 7),
  incl.cut       = 0.8,
  n.cut          = 1,
  return_details = TRUE
)

スイープ全体を記録するレポート

スイープは、たくさんの結果を作ります。読み手は、どの範囲を、どの設定で探索し、閾値ごとに何が出たかを、知る必要があります。generate_report() は、それをMarkdownファイルに書き出します。形式は2つあります。

  • "simple" は、本文や付録のための、短いレポートです。要約の表、閾値ごとの解、QCAパッケージで結果を確かめるためのコードが入ります。
  • "full" は、補足資料のためのものです。分析の概要(スイープの範囲と基準値)、記述統計に加えて、閾値ごとに、真理表、解の適合度、項ごとの指標、構成図、QCAパッケージの出力、再現に必要な設定が入ります。そのあとに、閾値どうしの比較が続きます。
report_file <- tempfile(fileext = ".md")
generate_report(res_ots, report_file, dat = demo, format = "simple")

書き出されたファイルの、最初の数行です。自分のコンピュータでは、"ots_report_simple.md" のような、きちんとした名前を付けると、作業フォルダにファイルができます。

構成図

QCAの論文では、解を図で示すことがよくあります。経路ごとに1列、条件ごとに1行で、「あり」は塗りつぶした円、「なし」は斜線を入れた円、「関係ない」は空白にします。経路のリストから、config_chart_from_paths() で描けます。

paths <- c("A*B*~C", "A*D", "B*E")
cat(config_chart_from_paths(paths))
Condition T1 T2 T3
A ● ●
B ● ●
C ⊗
D ●
E ●

● = presence, ⊗ = absence, blank = don’t care

円の記号を印刷できない雑誌などのために、普通の文字がよいなら、ASCII版を使います。

cat(config_chart_from_paths(paths, symbol_set = "ascii"))
Condition T1 T2 T3
A O O
B O O
C X
D O
E O

O = presence, X = absence, blank = don’t care

QCAパッケージで、セルを確認する

ThSQCAは、新しい結果を作り出すわけではありません。どのセルも、普通のQCA分析なので、どのセルでも、手で再現できます。これは、道具への信頼を築く、よい方法で、査読者に聞かれたときの答えにもなります。ここでは、アウトカム閾値が7のセルを再現します。

bin <- function(x, t) as.integer(x >= t)

d7 <- data.frame(
  LOY = bin(demo$LOY, 7), QUA = bin(demo$QUA, 7),
  SER = bin(demo$SER, 7), ENV = bin(demo$ENV, 7)
)

tt  <- truthTable(d7, outcome = "LOY", conditions = c("QUA", "SER", "ENV"),
                  incl.cut = 0.8, n.cut = 1, show.cases = FALSE)
sol <- minimize(tt)
sol

M1: QUA*SER -> LOY

minimize() が出力した解は、第1回のスイープ表の thrY = 7 の行(QUA*SER)と一致します。どちらも、データを同じ方法で二値化し(得点が7以上なら、集合に入る)、どちらも、同じQCAの関数が最小化を行ったからです。

ソフトウェアのバージョンを記録する

結果は、Rやパッケージのバージョンに左右されることがあります。表示して、レポートと一緒に保管してください。

c(R      = R.version.string,
  QCA    = as.character(packageVersion("QCA")),
  ThSQCA = as.character(packageVersion("ThSQCA")))

スイープを報告するための、短いチェックリスト

スイープは、探索する自由を与えるので、透明であることも求めます。報告する前に、次の問いのすべてに、「はい」と答えられるか、確かめてください。

  1. 閾値の範囲と、値の間隔を、結果を見る前に決めたか。
  2. 固定したすべての設定(一貫性閾値、頻度閾値、解の種類、方向性の期待)を書いたか。
  3. 解がないセルも含めて、格子のすべてのセルを報告したか。
  4. 格子の端のセルの背後に、事例が何件あるかを確かめたか。
  5. あるセルに最小解が複数あったなら、そのことを書いたか。
  6. スイープを、最良の閾値を探す作業として示すことを、避けたか。
  7. R、QCA、ThSQCAのバージョンを記録したか。
